# NMR Metabolomics Foundational Model

Self-supervised pretraining and downstream classification for 1D NMR
metabolomics spectra. The project trains transformer-based foundation models
on unlabeled spectra using masked-reconstruction and jigsaw (patch-shuffle)
pretext tasks — individually and jointly — then evaluates how well the
learned representations transfer to disease/phenotype classification across
several small-sample metabolomics datasets (LOOCV / k-fold), compared against
classical ML baselines (logistic regression, SVM, XGBoost).

## Repository layout

```
code/
├── preprocessing/   # spectral alignment, water/EDTA-peak suppression, normalization, deduplication
├── training/        # SSL pretraining: masked autoencoder, jigsaw, joint masked+jigsaw, plus earlier CNN/transformer experiments
├── evaluation/       # LOOCV / k-fold classification, few-shot, gradient analysis, per-dataset eval scripts
├── plotting/         # comparison plots and figures over evaluation results
└── utils/             # small .npy inspection utilities

data/          # (gitignored) raw and processed spectra, grouped by source dataset
models/        # (gitignored) SSL and classifier checkpoints
results/       # experiment outputs: metrics, plots, diagnostics, model-architecture artifacts
docs/          # workspace inventory and organization notes
```

See `docs/ORGANIZATION.md` for a fuller breakdown of the layout and
`docs/script_catalog.csv` for a per-script purpose index.

### Not tracked in git

Per `.gitignore`, the following are **not** in this repository and must be
supplied/generated locally:
- `data/` and `models/` (entire directories — raw/processed spectra and
  checkpoints)
- Any `*.npy`, `*.npz`, `*.pth` file anywhere in the repo (so binary arrays
  and checkpoints inside `results/` are also excluded — only metrics/plots/
  configs land in git)
- `.venv/`, `__pycache__/`, `*.pyc`, `.DS_Store`

`results/` directories therefore contain the CSVs, JSON configs, and PNGs
from an experiment, but not the raw prediction arrays or model weights that
produced them — those are regenerated by rerunning the corresponding
training/evaluation script.

## Pretraining approaches (`code/training/`)

| Script | Approach |
|---|---|
| `trainer_revised.py` | Masked-reconstruction autoencoder (`NMRMaskedAutoencoder`) — mask random spectral patches, reconstruct them |
| `train_jigsaw_spectra.py` | Jigsaw pretext task — shuffle spectral bins, predict original bin order, at one or more bin resolutions (256/512/1024/2048) |
| `train_joint_ssl.py` | Joint model combining masked-reconstruction and multibin jigsaw objectives in a single shared transformer encoder |
| `autoencoder.py`, `transformer.py`, `transformer_augment.py`, `CNN_ContrastiveLearning.py` | Earlier/alternative architecture experiments |

## Downstream evaluation (`code/evaluation/`)

Each dataset generally has a `*_loocv.py` (or `*_cv10.py`) script per model
family (classical / masking / jigsaw / joint SSL), plus a combined runner:

- `barth_all_models_loocv.py` — Barth Syndrome dataset, all families in one run
- `brc_t2d_*_loocv.py`, `brc_t2d_*_cv10.py` — BrC/T2D dataset
- `mtbls326_*_loocv.py`, `mtbls563` equivalents — MTBLS326/MTBLS563 datasets
- `joint_ssl_eval_common.py` — shared helpers for building/fine-tuning a
  classifier head on top of a joint-SSL checkpoint
- `fewshot_ml_comparison.py`, `prototype_fewshot.py`, `run_*_sweep_comparison.py` — few-shot and support-set sweep experiments
- `gradient_analysis.py` — saliency/gradient diagnostics on trained models

Each LOOCV/CV run writes a `summary.csv` (per-model metrics), out-of-fold
predictions, and a `run_config.json` recording the exact CLI args and
checkpoint path used — so any `results/` output is traceable back to the
model and settings that produced it. See any `results/loocv/*/README.md`
(where present) for a per-experiment writeup.

## Plotting (`code/plotting/`)

Scripts that read one or more `summary.csv` files and produce comparison
figures (ranked bar charts, heatmaps, fine-tuning trend lines, ROC/PR
scatterplots) — see `plot_barth_all_models_comparison.py` and
`plot_brc_t2d_loocv_comparison.py` for the current conventions.

## Datasets

Evaluation covers several independent metabolomics cohorts: Barth Syndrome,
BrC/T2D, MTBLS326, MTBLS563, TBI Tirupati, plus general plasma/serum spectra
used for SSL pretraining. Raw and processed arrays live under `data/<name>/`
locally (not committed — see above).

## Getting started

1. Place/generate the required `.npy` spectra and metadata under `data/`
   (see `code/preprocessing/` for alignment/suppression/normalization
   scripts that produce them from raw exports).
2. Pretrain an SSL model, e.g.:
   ```bash
   python code/training/train_joint_ssl.py \
     --data-path data/combined/combine_unique_Water_EDTA_Suppressed.npy \
     --out-dir results/joint_ssl \
     --model-dir models/joint_ssl
   ```
3. Evaluate on a downstream dataset, e.g.:
   ```bash
   python code/evaluation/barth_all_models_loocv.py \
     --families joint_ssl \
     --joint-checkpoint joint_ssl=models/joint_ssl/<run_name>/<run_name>_best.pth \
     --output-dir results/loocv/<experiment_name>
   ```
4. Compare results across models/experiments with the scripts in
   `code/plotting/`.
